# mixle-mlops 0.7.0 release checklist

This is the first release-readiness pass this repository has gone through — there is no prior
`release-checklists/` folder, `CHANGELOG.md`, or CI configuration to build on, and the package
version has been stuck at `0.1.0` in `pyproject.toml` since the very first commit (including at the
existing `v0.6.2` git tag/branch). This file follows the same gate structure and evidence discipline
as `mixle` core's `release-checklists/0.7.0.md` and `README.md`, adapted to this repo's actual
tooling (no CI, no Sphinx docs, a Docker/Helm/Terraform deploy surface instead of a hosted docs
site, and not currently published to any package index).

**Status legend**: `TODO` (no evidence yet) / `PARTIAL` (evidence doesn't cover the exact release
commit or is incomplete) / `DONE` (verified against the exact commit to be released, evidence
recorded inline) / `EXCLUDED` (explicitly out of scope, one-line reason).

**Scope note** (mirrors `mixle` core's own): this tracks `mixle-mlops` itself. Cross-package
coordination (lockstep versions with `mixle`/`mixle-agent`/`mixle-knowledge`/`mixle-pde`, family
co-install, publication order) is the release owner's responsibility, tracked outside this repo.

## Findings for the release owner (not fixed in this pass — judgment calls, not "bugs")

- **No CI configured at all** (§1/§8). Every other gate in this checklist that would normally be a
  CI run had to be done as a local, manual, one-time verification instead. Worth standing up before
  future releases lean on this checklist's speed.
- **No `LICENSE` file** despite `license = "MIT"` in `pyproject.toml` (§3). Needs a copyright-holder
  decision (personal vs. institutional, see the gate's evidence) before adding one.
- **No `CONTRIBUTING.md`/`SECURITY.md`** (§7), unlike `mixle` core.
- **`ruff format --check` would reformat 130/152 files** (§5) — this repo has apparently never run
  it; not attempted here as it's a large, unrelated diff and not this repo's own documented
  convention (only `ruff check` is documented).
- **`test_bridge_end_to_end_with_mixle_stack`'s `SeekIndex` ordering sensitivity** (§5) — flagged
  upstream in `mixle` core; whether `SeekIndex.slice()` under a capped search budget is *supposed*
  to guarantee strict ordering is a question for that repo, not this one.
- **Cross-package floor coordination**: this pass only verified `mixle-mlops`'s own dependency on
  `mixle` core. It does not depend on `mixle-agent`, `mixle-knowledge`, or `mixle-pde` today, but if
  a future version pulls one in, that floor needs the same treatment §2 gave the `mixle` floor here
  (import-sweep against real published versions, not an assumed number) — tracked outside this repo
  per the Scope note above.
