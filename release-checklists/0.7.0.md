# mixle-mlops 0.7.0 release checklist

This is the first release-readiness pass this repository has gone through — there is no prior
`release-checklists/` folder, `CHANGELOG.md`, or CI configuration to build on, and the package
version has been stuck at `0.1.0` in `pyproject.toml` since the very first commit (including at the
existing `v0.6.2` git tag/branch). This file follows the same gate structure and evidence discipline
as `mixle` core's `release-checklists/0.7.0.md` and `README.md`, adapted to this repo's actual
tooling (no CI, a Docker/Helm/Terraform deploy surface).

**PyPI status (2026-07-12)**: the release owner has set up the `mixle-mlops` project on PyPI so 0.7.0
can publish there, and the docs (`README.md`, `docs/installation.rst`, `docs/quickstart.rst`,
`docs/release-notes.rst`) now describe `pip install mixle-mlops` as the standard install path ahead
of that publish. As of this pass, `pypi.org/pypi/mixle-mlops/json` and the same path on
`test.pypi.org` both 404 — no release has actually been uploaded yet (consistent with a trusted-
publisher registered ahead of the first upload, which doesn't make the project resolve via that
endpoint until a release lands). §11/Publication below stays `TODO` until an actual upload is
confirmed; don't treat the docs changes as evidence that 0.7.0 is live on PyPI.

**Status legend**: `TODO` (no evidence yet) / `PARTIAL` (evidence doesn't cover the exact release
commit or is incomplete) / `DONE` (verified against the exact commit to be released, evidence
recorded inline) / `EXCLUDED` (explicitly out of scope, one-line reason).

**Scope note** (mirrors `mixle` core's own): this tracks `mixle-mlops` itself. Cross-package
coordination (lockstep versions with `mixle`/`mixle-agent`/`mixle-knowledge`/`mixle-pde`, family
co-install, publication order) is the release owner's responsibility, tracked outside this repo.

**Merge note (2026-07-12)**: the first pass of this checklist (through commit `ff4c777`, 2026-07-11)
verified `release/0.7.0` as branched directly off `origin/main`. That pass had no visibility into a
separate, unpushed local branch (`release/0.6.3-generic-capabilities`) carrying 29 additional commits
of real, tested capability — the `pool`, `substrate`, `telemetry`, and `verbs` gateway routes, the
drift-retrain end-to-end tests, served-model certificate/calibration manifests, a full Sphinx manual,
and a new frontend runtime console — that had never been merged to `main` and so was invisible to
that first pass. This update merges that work into `release/0.7.0`, re-verifies every gate below
against the combined tip, and documents what changed as a result. Every `DONE` gate from the first
pass was re-run rather than assumed still valid.

**Feature addition (2026-07-12)**: added LoRA/QLoRA fine-tuning depth requested for this release —
SFT (chat-template + prompt masking) and `resume_from` checkpoint continuation in the generated
training script, `adapter_path` support in `HFLogitProvider`/`load_local_engine` (previously nothing
in the serving path could load a trained adapter at all), and `POST /v1/models/load` (admin-gated)
to bring a completed fine-tune live without a gateway restart. See §5 for the real, non-mocked
verification (a genuine tiny model was LoRA-fine-tuned, saved, and reloaded through the actual
serving code, both with and without the fix a first attempt needed) and `docs/gateway-capabilities.rst`
for what's deliberately out of scope (per-request multi-tenant adapter switching).

## Findings for the release owner (not fixed in this pass — judgment calls, not "bugs")

- **`ARCHITECTURE.md` is stale well beyond this release's changes.** It describes an early 7-phase
  build plan and a much smaller module set (`monitoring/` instead of the actual route/service
  breakdown) — no mention anywhere of `compute`/`training` (LoRA/QLoRA), `evolve`, pool, substrate,
  telemetry, verbs, drift retraining, RAG, MCP, or the frontend runtime console. This almost certainly
  predates this release's work entirely and wasn't caused by it, but it means the one document titled
  "architecture" doesn't describe roughly half of what the package actually does today. Worth a
  dedicated rewrite pass, not a patch — inserting one feature's worth of updates into an otherwise
  7-phases-old document would look more current than it is.
- **The core finding of this pass**: 29 commits of real, tested capability (pool/substrate/verbs/
  telemetry routes, drift-retrain end-to-end tests, model manifest certificates) sat on a local-only
  branch that was never pushed to `origin` or merged to `main`, invisible to the first release-prep
  pass. Worth a process fix going forward — e.g. pushing feature branches even before they're ready
  to merge, so a release-prep pass run from a fresh clone can at least discover them exist.
- **No CI configured at all** (§1/§8), unchanged from the first pass. Every gate that would normally
  be a CI run had to be done as local, manual, one-time verification instead — now doubly true with
  a larger route surface to keep re-verifying by hand on every future change.
- **`docs/example-execution-manifest.rst` states its own requirement has not been met**: every one of
  the 11 example scripts under `examples/` must be recorded `passed`/`failed`/`timed_out`/`blocked`/
  `skipped` before public release, and none of this pass's verification work actually ran or
  classified them (several need GPU or live provider credentials this environment doesn't have).
  This is a real, currently-true gap the manual itself flags — not fixed here because it needs actual
  execution, not a documentation edit.
- **No `CONTRIBUTING.md`/`SECURITY.md`** (§7), unchanged from the first pass.
- **`ruff format --check` would reformat 141/182 files** (§5) — unchanged finding, updated count.
- **Cross-package floor coordination**: unchanged from the first pass — this package depends only on
  `mixle` core today.
- **`ruff format --check` is still not part of this repo's documented lint gate** even though the
  merged-in Sphinx docs pass and this pass's own commits were both written compatibly with it;
  standing up `ruff format --check` in CI (once CI exists at all) would prevent the gap from growing
  further before someone eventually pays down the existing 141 files.
